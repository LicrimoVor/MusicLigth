## Music Light

### Настольное приложение

```powershell
.\.venv\Scripts\python.exe app\main.py
```

Аудио захватывается непрерывно в отдельном потоке: читаются доступные пакеты
без ожидания заполнения блока. Буфер записи на 4096 отсчётов даёт запас при
задержках планировщика; окно анализа — 1024 отсчёта с шагом от 512 отсчётов.
При разрыве записи история детектора сбрасывается, а интерфейс сообщает о
пропуске данных. Захват продолжается без перезапуска приложения.

Интерфейс обновляется примерно 60 раз в секунду. График показывает последние
8 секунд, сигнал детектора, отклик и отметки найденных ударов. Спектр использует
логарифмические полосы и абсолютный уровень: тихий сигнал не растягивается до 100%.

Сила удара сжимается плавно, без скачка сразу до 100%. Световой отклик удерживает
пик 120 мс и затем плавно спадает; всплески с интервалом меньше 240 мс и слабые удары
между сильными не перезапускают импульс. Небольшие изменения уровня игнорируются,
скорость смены цвета и яркости ограничена. «Плавность» управляет скоростью
переходов: меньшее значение делает их спокойнее.

В группе «Бит и алгоритм» настройка «Обновления ламп» задаёт лимит команд
для каждой лампы: по умолчанию 20 в секунду, доступный диапазон — 5–30.
Медленная лампа не задерживает остальные: у каждого устройства своя отправка
и одно последнее ожидающее состояние, включая выключение. Повторные команды
включения и режима и изменения RGB до 3 единиц пропускаются.

Музыкальные команды отправляются без ожидания ответа. Пришедшие ответы читаются
перед следующей командой, чтобы не накапливались в постоянном соединении.
Нейтральные оттенки в музыкальном режиме также используют RGB, сохраняя режим.
Статичный цвет, выключение и диагностика ожидают ответ. Для одинакового цвета
в музыкальном режиме остаётся обновление раз в секунду. При ошибке связи повторы
откладываются на 2–30 секунд. Контроллер веб-сервиса сохраняет лимит 8 команд/с.

Проверки без подключения к лампам и записи реального аудио (проверки плеера
используют настоящее устройство вывода, воспроизводя тишину с нулевой громкостью):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

### Музыка и плеер

Зависимости устанавливаются в существующее окружение; для чтения тегов и обложек
добавлен `mutagen==1.47.0`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app\main.py
```

1. Откройте главную вкладку **Музыка**, добавьте файлы, папку или перетащите музыку
   в таблицу. Поддерживаются MP3, WAV, FLAC, OGG/Opus, AIFF и другие доступные
   SoundFile форматы. Статусы: Pending → Analyzing → Ready либо Error.
2. Дождитесь Ready для первого трека. Анализ идёт в одном фоновом рабочем потоке;
   его можно отменить или запустить повторно. Первое использование beat tracker
   может занять больше времени из-за компиляции функций librosa/Numba.
3. Создайте плейлист в главной вкладке **Плейлист**, добавьте в него выделенные треки из библиотеки.
   Плейлисты переключаются вкладками. Таблица показывает название, исполнителя,
   длительность, число прослушиваний и цветной статус Ready / Error / Не скачан.
   Меняйте порядок перетаскиванием либо через меню по правой кнопке мыши на треке.
   В этом меню доступны воспроизведение, переименование, анализ, поиск другой записи и удаление.
   Прослушивание учитывается после завершения трека, включая каждый повтор;
   пауза, перемотка и ручное переключение сами по себе счётчик не увеличивают.
4. Выберите источник **Музыка** в шапке и откройте **Управление**.
   Здесь выберите Calm, Rhythm или Spectrum, отметьте лампы,
   задайте группы, интенсивность, яркость и лимит команд. В новом режиме начальный
   лимит — 10 команд/с на лампу; диапазон настройки — 1–30.
5. Нажмите **Play playlist** или кнопку воспроизведения в шапке. Источник
   автоматически переключится на **Музыка**. Плеер всегда доступен сверху:
   текущая песня, предыдущая/следующая, воспроизведение/пауза, остановка,
   громкость, перемотка, повтор и микс. Кнопка **Очередь** раскрывает список треков.
   Кнопка **↻ N** добавляет один дополнительный повтор текущей песни при каждом
   нажатии. Счётчик уменьшается после завершения, при нуле начинается следующий трек.
   Правая кнопка мыши сбрасывает повторы; ручное переключение также их сбрасывает.
6. Для возврата к захвату звука выберите **Реальное время**, затем нажмите «Старт»
   во вкладке **Управление**. Панель настроек переключается вместе с источником;
   библиотека, плейлисты и шапка плеера остаются доступны.
   Два режима не отправляют команды одновременно; настройки Live сохраняются
   отдельно. Если следующий трек ещё анализируется, плеер ждёт Ready без опроса
   в цикле и автоматически продолжает очередь.

Вкладка **Бит** и спектр обновляются в обоих режимах, даже когда открыта другая
вкладка. Для плеера графики берут данные подготовленного анализа по позиции
аудиодвижка с частотой до 50 Гц; лимит команд лампам на частоту графиков не влияет.
Отрисовка истории ограничена 30 кадрами/с и использует растровые линии без дорогого
сглаживания сложных контуров. При скрытой вкладке таймер отрисовки выключен,
история продолжает пополняться.
В режиме статичного света live-захват также строит графики при наличии выбранного
аудиоустройства, сохраняя статичный цвет ламп.

**F9 / F10** переключают предыдущую / следующую песню. В Windows используются
системные [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)
с запретом автоповтора клавиши: они работают и при свёрнутом окне, без фонового
опроса клавиатуры. При закрытии регистрация освобождается. Если другая программа
уже заняла клавишу, приложение показывает это в строке состояния.

**Синхронизация.** Плеер использует `QAudioOutput.processedUSecs()` — часы обработки
PCM-аудио. Таймер только запрашивает эту позицию: время композиции не вычисляется
из системных часов. Аудио читает Qt из локального файла, сетевые операции выполняются
независимо. При перемотке, смене трека и источника увеличивается поколение команд:
устаревшие ожидающие отправки отбрасываются, новая сцена вычисляется сразу для
текущей позиции. У каждой лампы одна выполняемая и одна заменяемая ожидающая команда.
Медленная или недоступная лампа не блокирует остальные.

Ритмические огибающие и сглаживание рассчитываются с доступом к будущим кадрам:
максимум акцента приходится на метку доли, без задержки причинного live-фильтра.
Готовые состояния хранятся с частотой 20 Гц и интерполируются; реальная отправка
дополнительно ограничивается выбранной частотой команд.

Положительная компенсация задержки сдвигает свет вперёд относительно аудиопозиции.
Можно задать общую компенсацию и отдельную для каждой лампы. Кнопка измерения делает
три локальных запроса статуса и предлагает половину медианного RTT, исключая ожидание
в очереди контроллера. Это оценка сетевой задержки, а не оптическое измерение реакции
светодиодов: окончательный offset подбирается вручную.

**Хранение.** Библиотека и аудиокэш находятся в `app/data/music/`; воспроизведение
и анализ выполняются локально:

- `library.json` — библиотека, плейлисты, группы и настройки;
- `analysis/<SHA256>-v<version>/` — признаки, доли, onsets, динамика, обложка и метаданные;
- `timelines/<key>/` — отдельный кэш событий и готовых состояний света;
- `audio/<SHA256>.wav` — PCM-копия 48 кГц, stereo, 16 бит для воспроизведения через Qt.
- `downloads/<key>/` — загруженное аудио и сведения об источнике для повторного использования без сети.

Оригинальные файлы не перемещаются и не удаляются. После перезапуска SHA256 и версия
проверяются в фоне; неизменившиеся треки не декодируются и не проходят FFT повторно.
Смена пресета пересоздаёт только таймлайн. Длинные файлы декодируются блоками,
матрицы признаков и света открываются через memory mapping, вся библиотека в RAM
не загружается. PCM-кэш занимает примерно 11,5 МБ на минуту музыки; удаление записи
из библиотеки не удаляет общий кэш, который может использоваться другим треком.

**Ограничения.** Темп оценивается как глобальный BPM с уверенностью; сильные
энергетические акценты отделены от beat tracking. Музыкальный размер и такты не
угадываются, сложный ритм и смены темпа могут требовать другого пресета. Build Up
и Drop создаются только при выраженном изменении усреднённой энергии. Лимит Tuya,
Wi-Fi и внутренняя обработка лампы не позволяют обещать нулевую физическую задержку.
Уже отправленный TCP-пакет отозвать невозможно. Вывод идёт на системное аудиоустройство
по умолчанию с поддержкой PCM 48 кГц stereo; при его недоступности показывается ошибка.

Ключевые модули: `app/music/storage.py`, `analysis.py`, `timeline.py`, `jobs.py`,
`audio_backend.py`, `player.py`, `scheduler.py`, `metadata.py`; интерфейс —
`app/ui/MusicPanel.py`. Новые пресеты добавляются в `music.timeline.PRESETS`.

### Импорт HTML-плейлистов и поиск музыки

Отдельная утилита разбирает оба варианта скопированного HTML списка VK из
`app/data/*.txt`. Она сохраняет названия, исполнителей, длительности и ссылки
в `app/data/playlists/*.json`, удаляя повторяющиеся записи внутри плейлиста:

```powershell
.\.venv\Scripts\python.exe app/import_playlists.py app/data
.\.venv\Scripts\python.exe app/import_playlists.py "D:\Music\playlist.txt" --output app/data/playlists
```

В приложении есть одна кнопка **Плейлист → Импорт** в общей строке действий.
В текстовое поле можно вставить смешанный список: каждая непустая строка — ссылка
VK / YouTube / Яндекс Музыки либо `Исполнитель — название`. Тип определяется
автоматически. Ссылка на плейлист создаёт отдельную вкладку, одиночные песни
добавляются в текущую. Кнопка внутри диалога позволяет выбрать файлы HTML / TXT / JSON.
Ошибки отдельных строк показываются отдельно, доступные строки продолжают импортироваться.

YouTube импортирует метаданные трека или плейлиста и сохраняет точную ссылку для
скачивания. Яндекс Музыка импортирует публичные метаданные треков, альбомов и
плейлистов. VK использует уже сохранённые списки либо доступный HTML страницы;
если VK требует вход, можно вставить скопированный HTML прямо в поле или выбрать
его TXT-файл. Приложение не запрашивает пароли от музыкальных сервисов.

При запуске читаются готовые JSON; HTML разбирается автоматически только при первом
запуске без сохранённых списков. Последующие изменения исходных TXT нужно импортировать
явно. Пользовательские порядок, добавления и удаления сохраняются в `library.json`.

Двойной щелчок по треку или **Play playlist** запускает параллельный поиск по
названию на YouTube и SoundCloud через [yt-dlp](https://github.com/yt-dlp/yt-dlp).
Сначала сравниваются исполнитель, название и длительность; каверы, live, remix,
slowed, sped-up, bass boosted и другие версии отбрасываются, если они не запрошены
в названии. Среди подходящих записей предпочтение получают точная длительность,
официальное аудио / Topic и доступные аудиоформаты лучшего качества.

Загрузчик проверяет форматы до скачивания: исключает превью, DRM и низкую частоту
дискретизации, не принимает известный битрейт ниже 128 кбит/с для MP3/AAC либо
96 кбит/с для Opus. Lossless-форматы поддерживаются, если их отдаёт источник.
Эти характеристики относятся к исходному потоку, конвертация в WAV не улучшает
качество записи сама по себе. Метаданные не позволяют гарантировать качество
исходного мастера или распознать каждую неудачную перезапись на слух.

Выбранное аудио скачивается, конвертируется в PCM через FFmpeg из
[imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg), анализируется и передаётся
встроенному плееру. После скачивания проверяются фактическая длительность, наличие
звука и чрезмерная перегрузка. При ошибке или плохой записи пробуется следующий
кандидат, отказ одного поискового сервиса не блокирует другой. Поиск и проверка
метаданных используют не более двух одновременных запросов-процессов.
Все эти операции идут в фоне. Полная библиотека заранее не скачивается.
Повторное воспроизведение использует локальный аудио- и аналитический кэш.
Отсутствие подходящего результата или недоступность сервиса отображается как ошибка трека.

Если запись уже скачана неудачно, выделите её в **Музыке** или **Плейлисте** и
нажмите **Другая запись**. Приложение ищет по названию в обоих источниках и исключает
ранее отвергнутые ссылки. Новая версия проходит анализ перед заменой; при ошибке
старый файл, статус и число прослушиваний сохраняются. Если песня играет, после
успешной замены новая запись начинается с начала. Другие локальные файлы не меняются.
В шапке плеера и подсказках таблицы доступны источник, кодек, исходный битрейт и ссылка.
Импорт по точной ссылке YouTube сохраняет выбор записи; **Другая запись** позволяет
перейти от такой ссылки к поиску по названию. Старый кэш не перескачивается автоматически.

Строки с названиями в окне **Импорт** добавляют записи без скачивания заранее, а
**Добавить файлы** в разделе **Плейлист** добавляет локальное аудио в текущую вкладку.
**Микс** выбирает случайный первый трек и перемешивает только текущий плейлист;
каждый трек проходит один раз до конца очереди, если для него не добавлены повторы
в шапке плеера. Для поиска и первой загрузки требуется интернет; ключ API не нужен.

### Веб-сервис пресетов

Лампы берутся из `app/core/lamps.json`. Пресеты хранятся локально в
`backend/data/presets.json`, SQL не используется.

Пароли задаются через переменные окружения или `.env`:

```env
MUSICLIGHT_ADMIN_PASSWORD=change-admin-password
MUSICLIGHT_USER_PASSWORD=change-user-password
MUSICLIGHT_DRY_RUN=0
```

Для локальной проверки без отправки команд на лампы:

```powershell
python -m backend.server --host 127.0.0.1 --port 8000 --dry-run
```

Для работы с реальными лампами:

```powershell
python -m backend.server --host 0.0.0.0 --port 8000 --live
```

После запуска откройте `http://127.0.0.1:8000`. Если пароли не заданы,
используются локальные значения `admin` и `user`.

При старте backend один раз запускает диагностику ламп и сохраняет результат
в `backend/data/state.json`. В админ-панели есть кнопка `Проверить`, которая
повторяет диагностику вручную.

В редакторе пресета каждая лампа включается в пресет отдельно. Если лампа не
отмечена, backend отправляет ей явную команду выключения через switch DP.
Эффекты `Огонь`, `Пульс` и `Волна` запускаются backend-циклом и работают до
применения следующего пресета.
